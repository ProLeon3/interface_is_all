使用指南.

在这里约定模块与接口，在编程工具中实现，再回来核对代码。

先选择要工作的项目

工作台读取你选定的本地目录，帮助你设计架构和检查实现。点击「选择项目」输入路径或浏览目录，无需重启；选择只影响当前标签页，刷新后仍会恢复。

新项目：先设计，再实现

  1. 在 coding agent 中讨论需求；可从这里导出设计请求，或手动创建模块。导入 agent 提案后审阅变更，接受为草稿，再单独确认。
  2. coding agent 读取已确认设计后实现；也可通过「交接已确认设计」导出 JSON。
  3. 完成代码后回到「代码检查」，运行依赖检查；接口能力与职责由外部审查工具核对，再导入结果审阅。

已有 Go 项目：从代码开始

  1. 从「分析已有代码」导出源码请求，交给 coding agent 分析。在「设计工具」导入 agent 提案。
  2. 核对图上的模块、接口与源码依据，接受提案为草稿，再审阅确认整个设计版本。
  3. 确认后即可进入「代码检查」，无需先交接或重新实现。有问题时调整设计或代码，再次检查。

有了已确认设计，就可以在设计和检查之间来回工作。修改或保存草稿不会切换检查基准，只有再次确认才会替换它。

依赖检查只检查明确禁止的直接包引用，不会自动运行接口能力审查，也不代表业务功能正确。能力审查的模型判断始终需要你核查。

命令行与文件协作

也可以通过命令行启动工作台、由外部工具写入草稿，或查看已确认设计并运行检查：

archdesign serve -addr 127.0.0.1:8090
archdesign design-request -project /你的项目目录 -kind initial_analysis
archdesign proposal-import -project /你的项目目录 -file response.json
archdesign show -project /你的项目目录
archdesign check -project /你的项目目录

草稿保存在 .architecture/draft.json，在工作台审阅确认后才成为实现与检查约束。交接 JSON 包含确认版本、完整设计和实现说明。

在「代码检查」的「能力审查」中导出请求、导入响应，或由 coding agent 调用 review-request 和 review-import。

目前支持共享项目文件、设计同步和报告展示。由 coding agent 主导调用；自动触发和 skill 安装由外部工具接入。选中对象可随设计请求导出，工作台会同步展示外部导入的提案。
