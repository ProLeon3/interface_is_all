# 已有基准项目重新分析

> 2026-09-21 决策更新：按 [ADR-0002](adr/0002-external-coding-agent-orchestration.md)，重新分析改为「导出重新分析请求」并导入 agent 提案；下文 `POST /api/reanalysis` 与“发送给已配置模型”的描述保留为实施当时的记录，当前接口见 [README](../README.md)。浏览器回归脚本已于 2026-09-22 改为固定响应替身扮演 agent。

实现日期：2026-09-21。用户在首次接入完成后要求增加此功能，扩展原先后置的“重新分析源码并生成新草稿”流程。

## 使用流程

选择已有确认基准的 Go 项目，在「设计草稿」视图展开「调整设计」，选择代码分析方式，再点击「重新分析代码」。应用读取当前构建范围的源码，发送给已配置模型，生成忠实还原现状的提案。打开项目、刷新和查看旧基准不会触发源码分析或模型请求。

提案保留生成时的已保存草稿和完整旧基准。审阅区分别展示两份对照；模块、接口、协作仍可在图上核对，详情与图下展示源码依据、问题、建议和不确定项。切换到「已确认版本」时，显示该基准自己的历史证据。

分析期间及生成后，原草稿和旧基准保持原样。「接受并保存草稿」只替换草稿，可以继续手动编辑；最后「审阅并确认」才发布新基准。在此之前，依赖检查、能力审查请求和设计交接继续使用旧基准。

源码分析仍按代码现状生成，不把旧禁止规则当成代码事实。提案中的禁止规则为空，旧规则的移除会出现在差异中；需要保留的约束可在接受后编辑草稿恢复。模型会收到尽量沿用同义对象 ID 的要求，但程序不保证模型一定做到，仍需审阅。

分析目标、单个 Go module 的范围、构建条件、完整源码 1 MiB 上限及依据校验沿用[首次接入](initial-analysis.md)。未扩展其他语言、自动架构改造或代码修复。

## 状态与版本保护

| 阶段 | 行为 |
| --- | --- |
| 发起及生成完成 | 核对草稿指纹和原基准版本；生成完成再次核对源码和当前分析来源 |
| 接受提案 | 复核源码、草稿和原基准，只写草稿；旧提案不能重放覆盖新编辑 |
| 确认版本 | 对本次已接受的分析复核源码，发布新快照并保留原基准的父版本引用 |
| 设计内容未变化 | 仍允许明确确认新的源码证据，产生新的版本；重复确认同一份已确认内容保持幂等 |
| 未接受即撤回 | 保留原草稿、旧基准和不可变提案；没有待确认来源时释放审阅入口 |
| 已接受或接受中断后撤回 | 保留来源保护，必须重新分析并接受后才能确认；再次生成又撤回也不能清除此保护 |
| 生成失败或源码加载不完整 | 保留草稿、基准和旧证据；加载不完整时展示本次实际读取范围 |
| 后续手工调整设计 | 已经确认的历史分析不要求每次手工修改都重新分析；新待确认分析仍需复核 |

接受过程保留原有“先记录接受中、再写草稿、再标记已接受”的顺序。同一提案可恢复中断后的接受，其他窗口的新编辑会触发冲突。来源是否已经确认由快照引用推导，避免确认快照写入后、分析状态尚未更新时发生中断歧义。

重新分析不要求草稿文件一定存在。只有确认快照时，以该快照作为设计参考与原稿对照，接受后才创建草稿。历史确认文件保持原内容。

## 接口与兼容性

| 接口或字段 | 说明 |
| --- | --- |
| `POST /api/reanalysis` | 提供 `expected_draft_hash` 和非空 `expected_revision`，生成重新分析提案 |
| `POST /api/reanalysis/discard` | 按提案 ID、当前草稿和基准版本撤回，保留草稿及历史 |
| `POST /api/initial-analysis` | 保持原有只接受空基准的首次接入约定 |
| `GET /api/state` 的 `reanalysis_available` | 项目有有效确认基准且根目录存在 `go.mod` 时提供入口 |
| 提案的 `baseline` | 生成时完整的确认快照，随提案内容指纹一起校验 |
| 快照的 `source_analysis_id` | 本轮重新分析的永久证据引用；原 `initial_analysis_id` 继续保留首次来源 |
| `initial_analysis` 和 `.architecture/initial-analysis.json` | 为兼容沿用原名，记录首次或后续分析；新增派生 `confirmed` 状态及 `requires_acceptance` 保护标记 |

新字段按需写入。旧提案和旧快照没有这些字段时，其原内容指纹不变；不批量迁移或重写已有项目。提案继续调整、接受和设计确认沿用原有接口。
