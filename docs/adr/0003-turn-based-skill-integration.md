# 0003. coding agent 以回合制 skill 接入，程序不新增事件通道

- **状态**：Accepted（已接受）
- **日期**：2026-09-22
- **补充**：[ADR-0002](0002-external-coding-agent-orchestration.md) 留下的「具体接入形式和新增命令在后续实现中确定」。本决定不取代 ADR-0002。

## 背景

ADR-0002 确定了「外部 coding agent 调用本程序」的方向，程序已提供导出请求、导入提案、确认版本和检查等命令，但 skill 安装、选中对象同步与自动检查一直未接入。用户期望的使用方式是：在 coding agent 中输入 `/interface_design @spec.md`，agent 结合已有代码与需求生成设计；用户在浏览器工作台审阅、修改、确认；确认后的设计持久化并约束后续实现。

接入的核心约束是 coding agent 的回合制：agent 说完「请去浏览器确认」回合就结束，浏览器没有办法把用户的动作推进对话。已知一种可行的替代是 impeccable 的 live 模式：技能自带本机服务，agent 阻塞在一条长轮询命令上，浏览器事件到达时命令返回、agent 被唤醒；Claude Code 以后台任务承载，Codex 以前台会话承载。采用这种模式需要本程序新增事件队列、事件确认语义、超时与恢复机制，以及页面上「发送给 agent」的入口。

## 决定

我们将以一份可重入的 skill 作为接入形态，采用回合制：agent 每次被唤醒都从目标项目的 `.architecture/` 目录读取请求、提案、草稿和确认版本，据此判断当前阶段并执行下一步；用户在浏览器操作之后回到对话说一句话触发下一回合。程序不新增等待命令、事件队列或「发送给 agent」入口。

确认动作只在浏览器完成，skill 不代用户运行 `confirm`。回合制下 agent 可能在用户上次看图之后又改过草稿，对话里的一句「确认」无法证明用户看的就是将被确认的那一版；浏览器审阅窗口展示完整设计、要求审阅声明，并同时校验草稿指纹与预期版本，这套保护已经实现且经过回归，skill 不应绕开。

选择回合制的理由：用户判断一个「点击即感知」的实时体验不值得让程序长期维护事件队列；程序到浏览器方向的同步已由 3 秒轮询解决；浏览器导出的调整请求已经落在 `.architecture/requests/`，skill 可以直接把它当作输入。

## 后果

- 程序零改动，接入工作集中在 skill 的指令文本、安装方式与验收。
- 用户每次在浏览器操作之后都必须回到对话触发下一步，流程可能停在半路。skill 每个回合结束时必须给出明确的下一步操作，减少用户遗忘。
- agent 无法实时得知用户已确认；只能在下次唤醒时比较 `confirmed.json` 的版本。
- skill 不能依赖对话记忆，必须从文件重建阶段。agent 自己导出的请求与用户从浏览器导出的请求需要区分，默认做法是唤醒时先扫描尚无提案对应的请求并应答。
- 未来若需要实时感知，需要新的 ADR 取代本决定，且事件队列设计必须与现有写锁、版本保护和未保存编辑保护协调。

## 考虑过的替代方案

### 长轮询事件通道（impeccable live 模式）

未选择。需要新增事件队列、确认语义、恢复与超时处理；Claude Code 单条命令上限 10 分钟，用户思考更久时 agent 会被周期性空唤醒；Codex 前台阻塞期间用户无法与 agent 并行对话。用户认为为实时体验维护这些不值得。

### 事件通道为主、回合制兜底

未选择。兜底几乎免费，但主路径仍然需要事件队列，成本与上一项相同。

### 允许对话确认，由 agent 运行 `confirm`

未选择，理由见决定。要求用户在对话中复述草稿指纹作为审阅证据的折中方案，若将来采用需要新的 ADR。

## 实现状态

本决定已实施（2026-09-22）：`skills/interface_design/` 以回合制 skill 接入，每次唤醒由 `scripts/state.py` 从 `.architecture/` 重建阶段，程序零改动，确认只在浏览器完成。范围与阶段判断规则见[coding agent 接入实现依据](../../coding%20agent%20接入实现依据.md)，实现与验收记录见[interface_design skill：实现与验收记录](../agent-skill.md)。
