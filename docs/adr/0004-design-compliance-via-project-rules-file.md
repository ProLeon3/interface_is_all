# 0004. 设计遵循约束只通过目标项目的规则文件传递

- **状态**：Accepted（已接受）
- **日期**：2026-09-22
- **相关**：[ADR-0002](0002-external-coding-agent-orchestration.md)、[ADR-0003](0003-turn-based-skill-integration.md)

## 背景

用户确认后的设计只存在于目标项目的 `.architecture/confirmed.json`。新开的实现会话不会自动读取它；目前唯一的「请按设计实现」文字位于用户手动下载的交接包 `instructions` 字段中，不在项目里。用户要求「coding agent 后续实现时严格遵守模块与接口设计」，需要一个跨会话生效的机制。

[产品设计](../../产品设计.md)与[使用方式与交互](../../使用方式与交互.md)曾把「每轮任务完成后按 skill 流程发起架构检查，确定性违规先自动修复并复查」列为待验证目标。候选机制有三种：写入目标项目的规则文件；安装 Claude Code 的 Stop hook 自动运行 `archdesign check`；提供独立的实现 skill 组织读基准、实现、检查、修复、能力审查与汇报。

## 决定

我们将只通过目标项目的规则文件传递设计遵循约束。设计确认完成后，skill 向规则文件写入一段带起止标记的固定约定：实现前读取已确认设计；不得为迁就代码改写基准，需要变更时回到设计流程；每个任务完成后运行 `archdesign check` 并在对话汇报；接口能力与模块职责的偏离通过能力审查请求处理。不安装 hook，不提供独立的实现 skill。

规则文件是 Claude Code 与 Codex 共有的机制，零程序改动，删除标记块即可撤销。hook 仅对 Claude Code 生效，且要维护项目配置；独立实现 skill 无法约束用户直接在对话中发起的实现任务。用户选择先用最小机制验证遵循效果。

## 后果

- 是否遵守完全取决于 agent 的指令遵循，没有任何硬保障；确定性检查是否被执行，也依赖 agent 记得去跑。
- 产品文档中「每轮任务自动检查、确定性违规自动修复并复查」从产品目标降级为规则文件中的指令，不再作为产品承诺。
- 程序能硬检查的仍只有禁止的直接包依赖；接口能力与职责偏离继续依赖 agent 主动运行能力审查、用户核对结论。
- skill 需要修改用户项目的规则文件，属于对用户仓库的写入。写入使用标记块幂等替换，完成后在对话中说明，不代用户提交 git。
- 若实际使用中发现遵循率不足，可以通过新的 ADR 叠加 hook 或实现 skill；本决定不排斥叠加。

## 考虑过的替代方案

### 规则文件加 Stop hook

未选择。hook 为 Claude Code 专有，Codex 是否有等价机制未查证；用户不希望现在维护 hook 配置。

### 规则文件加独立实现 skill

未选择。无法约束用户直接发起的实现任务；其流程可以先作为规则文件中的文字存在，跑过几轮后再决定是否值得做成 skill。

## 实现状态

本决定已实施（2026-09-22）：interface_design skill 在检测到新确认版本后运行 `scripts/write-rules.py`，向目标项目已有的 `CLAUDE.md`/`AGENTS.md`（都没有则新建 `AGENTS.md`）写入带 `<!-- interface_design:begin revision=… -->` / `<!-- interface_design:end -->` 标记的块，幂等替换，块外内容不动，不提交 git；块内五条约定与本决定一致。见[coding agent 接入实现依据](../../coding%20agent%20接入实现依据.md)与[interface_design skill：实现与验收记录](../agent-skill.md)。
