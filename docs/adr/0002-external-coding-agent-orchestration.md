# 0002. 由外部 coding agent 主导流程，程序保留确定性能力

- **状态**：Accepted（已接受）
- **日期**：2026-09-21
- **取代（Supersedes）**：[ADR-0001](0001-use-standalone-design-workbench.md) 中由独立工作台承接 AI 设计、外部 agent 仅负责实现的决定。

## 背景

独立工作台已经承接图形展示、手动编辑、提案审阅、设计确认和检查，也包含直接调用模型生成设计、分析源码的流程。此前先独立验证设计交互，再接入外部 coding agent，原因记录于 ADR-0001。

用户决定保留程序中的确定性能力，将所有 LLM 推理交给已有的外部 coding agent，并明确选择由 agent 调用本程序。这样可以复用 agent 的对话、代码探索和模型能力，使本程序集中维护架构数据、图形交互和可重复执行的检查。

## 决定

由外部 coding agent 主导需求讨论、设计生成、源码理解、语义审查及实现修复，通过本程序提供的命令和结构化数据接口获取上下文、提交结果及运行检查。

程序保留确定性能力和架构状态管理。这里的确定性能力也包括有交互的图形编辑、提案审阅、保存与版本确认；是否涉及浏览器或状态变化，不是判断是否外移的依据。

| 参与方 | 职责 |
| --- | --- |
| 外部 coding agent | 承接需求与设计对话；生成、调整设计；归纳已有代码的模块与能力；执行语义审查；实现和修复代码；管理模型配置、提示词、对话上下文和调用流程 |
| 程序 | 采集源码、声明、依赖、构建范围和指纹；执行设计结构、引用关系、目录归属及禁止依赖检查；提供上下文和结果交换接口 |
| 本地工作台与存储 | 展示架构图、变更和证据；支持手动编辑、提案审阅、草稿保存和用户确认；维护历史、布局、项目隔离、版本冲突和未保存编辑保护 |
| 用户 | 决定需求和架构取舍；审阅语义结论；明确确认设计基准及其变更 |

调用方向为“外部 coding agent → 本程序”。程序不直接调用模型，也不通过工作台或 CLI 启动、管理 coding agent 或 LLM 审查进程。用户仍可独立使用程序的手动编辑、审阅确认和确定性检查。

外部 agent 的设计、分析和审查产物通过程序校验后进入相应的提案、草稿或观察结果流程，不能直接覆盖已确认快照。程序继续核对结构、引用、证据位置、源码指纹和设计版本；这些校验不证明语义判断正确。保存草稿或接受提案不等于确认设计，语义审查结论继续保持待确认。

例如，已有项目分析分为“程序提取事实 → agent 生成现状提案 → 程序校验并展示 → 用户审阅确认”。现状描述、问题和改进建议继续分开，初次分析不自动产生禁止依赖规则。程序负责提供确定的输入输出约定，外部 skill 可以说明如何使用这些约定；具体接入形式和新增命令在后续实现中确定。

## 后果

- 模型配置、对话和推理流程集中到外部 agent，本程序集中维护架构数据、校验和图形审阅。
- 需要维护上下文与结果交换约定，包括项目、源码范围、证据引用和版本关联。外部生成期间的源码或设计变更仍须在接收结果时检测，不能因调用方变成 agent 而跳过原有保护。
- 需求对话和模型生成操作转移到外部 agent；工作台中的图形编辑、差异展示和用户确认继续保留。选中对象等上下文如何传给 agent，需要后续接入实现。
- 自动检查、修复和结果同步依赖外部 agent 的流程及集成可靠性，需要单独验证。确定性检查通过仍不代表语义或业务功能通过验收。

## 考虑过的替代方案

继续由工作台直接调用模型，可以保留同页对话与生成，但需要本程序持续维护模型协议、配置和推理流程，不符合本次将 LLM 能力交给外部 agent 的分工。

由工作台启动外部 coding agent，可以移出模型客户端，但本程序仍要组织 agent 的启动、任务和结果回传。用户选择在已有 agent 对话中主导流程，因此未采用此方案。

## 实现状态

本决定已于 2026-09-21 实施。[designer](../../designer/designer.go) 不再包含模型 HTTP 客户端，只保留请求与响应协议、响应 Schema 和分析依据校验；外部审查执行器与 `review -reviewer` 命令已移除，程序不再读取 `ARCHDESIGN_AI_*` 配置。新增 `design-request`、`proposal-import`、`proposal-show`、`proposal-accept`、`proposal-discard` 命令，以及工作台 `POST /api/design-request`、`POST /api/proposal-import` 接口；页面入口改为「导出设计请求」「导出源码分析请求」和「导入 agent 提案」。请求保存在 `.architecture/requests/`，导入时核对项目绑定、草稿指纹、基准版本和源码指纹。`review-request`、`review-import` 继续供 agent 使用。

skill 安装、选中对象向对话同步、每轮任务后的自动检查与修复尚未接入。当前可运行功能和交换协议以 [README](../../README.md) 为准；浏览器回归自 2026-09-22 起由固定响应替身扮演 agent，见[核心用户旅程](../core-user-journeys.md)。
