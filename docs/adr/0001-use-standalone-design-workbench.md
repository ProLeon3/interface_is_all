# 0001. 先由独立工作台承接设计流程，再接入 skill

- **状态**：Superseded（已被取代）
- **日期**：2026-09-20
- **被取代（Superseded by）**：[ADR-0002：由外部 coding agent 主导流程，程序保留确定性能力](0002-external-coding-agent-orchestration.md)（2026-09-21）。下文保留原始背景和决定。
- **取代的约定**：[产品设计](../../产品设计.md)和[使用方式与交互](../../使用方式与交互.md)中“以外部 AI 编程工具及 skill 作为设计入口”的约定；这些文件不是旧 ADR，其原文保留为历史记录。

## 背景

原方案把需求与设计对话放在用户已有的 AI 编程工具中，通过 skill 与本地工作台协作，工作台负责图形展示、编辑和确认。当前项目已经具备手动编辑、保存、确认与检查能力，skill 集成和需求驱动的 AI 设计尚未完成。

用户决定先独立验证设计交互和设计产物的效果，再考虑集成到 coding agent。首轮需要让用户完成需求输入、图形化理解、修改与确认，并用确认后的设计开展一次实际开发。

## 决定

由独立的本地浏览器工作台承接需求输入、AI 设计、调整与确认，skill 集成后置。

用户在工作台中围绕接口协作图与 AI 讨论设计。外部 coding agent 继续负责代码实现，首轮手动交接已确认的设计文件。这样可以在不依赖 skill 集成的情况下，验证图形化设计过程及其对一次实际开发的帮助。

具体交互、当前实现差距和首轮验收以[独立图形工作台实现依据](../../独立图形工作台实现依据.md)为准。此决定已接受，不表示相关能力已经实现。

## 后果

- 设计过程集中于工作台，用户可以围绕所选模块和接口提出修改，并在图中审阅变更。
- 工作台需要新增 AI 调用、设计上下文传递和修改审阅能力，不能仅依靠外部对话与文件同步完成目标流程。
- 首轮承担手动交接设计文件的操作成本，外部工具自动同步与任务结束后自动检查的效果仍待后续验证。
- 一次实际实现只能提供初步可行性证据，不能证明长期架构控制或 skill 集成可靠性。

## 考虑过的替代方案

继续以外部 AI 编程工具对话、skill 接入和工作台同步展示作为首轮入口，可以复用用户已有的对话环境，但会把集成工作纳入独立验证之前。用户本次选择先验证独立工作台，因此将该集成方向后置。
