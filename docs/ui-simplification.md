# 工作台操作层级调整与复审

日期：2026-09-21。范围：主导航、架构设计页及检查页的操作入口，沿用现有设计存储、确认与冲突保护。

## 评审方法

先实际查看用户正在运行的工作台，再使用 `examples/todo` 和 `examples/shop` 的临时副本检查已有设计与空项目。采用双独立评审：A（`ux_design_assessment`）负责设计判断，B（`ux_browser_assessment`）负责浏览器与布局数据；A 完成后才合并 B 的结果。主代理据此给出修改意见，由一个实施代理（`ux_implementation`）修改，主代理再在真实浏览器复审。任务与实施授权明确，未追加偏好或权限问题。

桌面为 1440 × 900，手机为 390 × 844。按钮计数只统计设计页图外的功能操作，不计导航、模块索引、图中对象选择与拖动手柄；版本选择、折叠入口单独说明。画布位置使用从页面顶部计算的 CSS 像素。

## 修改前的问题与建议

| 问题 | 实际影响 | 修改方向 |
| --- | --- | --- |
| 多个阶段同时展示 | 已有设计首屏有 10 个执行操作、2 个版本选择；确认、重新分析、AI 修改都用主按钮样式 | 按起草、提案审阅、保存、确认、交接的状态确定主要操作 |
| 工作对象出现太晚 | 桌面图形滚动区从 y=822 开始，首屏只露约 78 像素；手机从 y=1211 开始 | 压缩标题，已有设计默认先显示图，修改与重新分析按需展开 |
| 空项目要求用户处理未来的事 | 尚无模块就要求填写修改意图、选择整个设计 | 先选择分析代码或从需求设计，只展示相应输入 |
| 低频工具与当前任务竞争 | 导入、导出、交接、新建与版本切换同排出现 | 文件操作进入有名称的工具入口；新建放到画布上下文；交接按确认状态呈现 |
| 选择范围与状态容易误解 | 初始图和详情选中 cli，AI 修改范围却是整个设计；手机隐藏版本摘要 | 统一对象选择，保留简短状态，明确返回草稿与下一步 |

## 验收标准

- 有设计时，桌面默认图从 350 像素以内开始，手机首屏能看到图；没有整页横向溢出。
- 当前阶段只有一个突出显示的主要操作，用户可以直接理解下一步；打开修改区后以该任务为焦点。
- 新项目、已有代码、已保存草稿、未保存修改、待审阅提案、已确认版本都能找到对应入口。
- 导入、导出、新建、布局、禁止依赖、模型配置、源码分析与证据、能力审查等功能仍可到达。
- 接受提案只保存草稿，确认仍需独立审阅；「接受并审阅确认」只是把两步连续执行，旧基准、未保存编辑、冲突保护保持有效。
- 收起的操作可用键盘展开；菜单可退出，轮询不会关闭用户正在使用的面板。

第一轮实施后，主代理实际查看已有设计、空项目代码分析、需求起草、待审阅提案的桌面和手机页面。结论：**本轮操作层级调整合格，未发现阻塞问题**。这表示下列范围通过复审，不代表已完成真实用户可用性研究。

| --- | ---: | ---: |
| 桌面首屏图外执行操作 | 10 | 4 |
| 桌面首屏主按钮（含禁用） | 3 | 1 |
| 桌面画布面板起点 | y=766 | y=230 |
| 桌面图形滚动区起点 | y=822 | y=286 |
| 手机图形滚动区起点 | y=1211 | y=404 |
| 桌面、手机整页横向溢出 | 无 | 无 |

修改后四个常显操作是交接已确认设计、调整设计、新建模块、整理布局；另有两个版本选择和一个「设计工具」折叠入口。没有把菜单入口算作功能消失，也没有把图中可选择的模块、接口、协作当成需要消除的按钮。

实际变化：

- 标题压缩为名称和当前状态。未保存时显示保存；草稿待确认时显示审阅；待审阅提案以接受为主；草稿与基准一致或查看基准时显示交接。
- 已有设计默认收起输入区。通过「调整设计」进入描述修改或代码分析；提案期间通过「继续调整提案」展开。
- 空项目仅展开选中的起草方式，隐藏修改意图与整个设计选择，保留手动创建及导入入口。
- 导入、导出和其他阶段的交接进入「设计工具」；提案下载及放弃进入「提案工具」；外部能力审查进入检查页的折叠区域。
- 初始选中对象、图上高亮和 AI 目标一致；选择整个设计会同步取消模块高亮。确认视图明确指向返回草稿编辑。

浏览器复审通过：设计工具可用 Enter 展开、Escape 关闭并恢复焦点，外部点击会关闭；轮询保留正在展开的修改区域；源码分析仍说明发送源码；确认视图不再指向隐藏表单；空态模式可以切换，无多主按钮竞争或页面异常。

程序验证：

- `go test ./...` 通过；前端及修改后的验收脚本语法检查通过。
- `scripts/verify-workbench.sh` 通过：手动模块与接口编辑、保存、完整审阅确认、检查、审查请求导出与响应导入、布局持久化、未保存编辑、延迟轮询、写锁重试及项目隔离。
- `scripts/verify-ai-workbench.sh` 通过：固定模型生成、继续调整、接口迁移、前后比较、接受与确认交接、旧提案拒绝覆盖及刷新恢复。
- `scripts/verify-initial-analysis.sh` 通过：初次分析、源码证据、跨窗口恢复、撤回重做、重新分析与旧基准对照、来源保护、相同设计的新证据确认及后续检查。

首次源码分析回归停在旧脚本直接等待已收起的「重新分析代码」按钮。脚本改为实际点击「调整设计」并切换分析方式后，定向复跑通过；没有为通过测试恢复常显按钮，也没有弱化原来的数据保护断言。

## 第二轮：澄清导航与先后关系

第一轮复审遗漏了主导航的信息层级。用户请首次使用者查看后反馈：「架构设计」「检查结果」「协作接入」是否有先后关系，页面无法说明。实际再次查看三个页面后发现，它们混放了工作区、检查动作和帮助说明，平行的视觉样式容易被理解为三个连续阶段。

真实的前置关系只有：**代码检查必须有一份已确认设计作为基准**。

| 使用情境 | 实际路径 |
| --- | --- |
| 新项目 | 起草并确认设计 → 交给外部编程工具实现 → 回来检查代码 |
| 已有 Go 代码 | 分析源码 → 审阅确认设计 → 直接检查现有代码 |
| 已有确认基准 | 可在设计与检查间反复往返；未确认的新草稿不替换基准 |

「协作接入」实际是使用说明，并非必须完成的接入操作。因此没有把导航改成强制分步向导，而是由同一个实施代理继续调整：

- 主导航保留「架构设计」，将「检查结果」改为「代码检查」，对应起草约束和执行检查两个工作区。
- 「协作接入」改为「使用指南」，移到桌面侧栏底部；手机在主导航下方单独提供文字入口。
- 未确认时，检查页只展示「先确认一份设计」、简短原因和「前往架构设计」，隐藏禁用动作及空报告。有基准后恢复全部检查与审查入口。
- 设计页增加随状态变化的流程说明，明确新草稿确认前继续使用旧基准。
- 指南分别解释新项目与已有代码的流程，命令行与文件协作默认收起。依赖检查和需人工核查的外部能力审查仍明确区分。

主代理实际查看了桌面和手机的检查空态、设计页、指南，以及已有基准的检查报告，第二轮复审合格。验证了返回设计按钮、唯一导航活动态、键盘展开高级说明、未保存草稿下运行旧基准检查和往返保留编辑。没有浏览器脚本异常或整页横向溢出；增加流程说明后，图形区桌面起点 y=314、手机 y=470，仍在首屏。

本轮重新执行 `scripts/verify-workbench.sh`，覆盖编辑确认、确定性与语义报告、同步冲突、布局和项目隔离。首次执行因脚本用完整名称匹配而无法识别带报告数量徽标的「代码检查」入口；改为保留数量后缀的名称匹配后重跑通过。源码分析与模型流程的验证记录属于第一轮，本轮没有重复调用模型。

证据：[检查空态桌面](verification/ui-simplification/nav-empty-checks-desktop.png)、[检查空态手机](verification/ui-simplification/nav-empty-checks-mobile.png)、[桌面指南](verification/ui-simplification/nav-guide-desktop.png)、[手机指南](verification/ui-simplification/nav-guide-mobile.png)、[设计页](verification/ui-simplification/nav-design-desktop.png)、[检查报告](verification/ui-simplification/nav-confirmed-checks-desktop.png)、[导航复审数据](verification/ui-simplification/navigation-review.json)。

## 工具与证据边界

Impeccable 上下文加载器、评审存储命令和检测器均因本地缺少引擎而无法运行；检测器实际退出码为 127，没有结果，不能记作零问题。没有启动检测器服务或注入覆盖层。本轮采用源码、独立评审、实际浏览器截图及 DOM 数据补充验证。

评审时只读查看用户的 8090 服务，交互验收使用临时项目副本。通过验收后，使用原有 `scripts/start-workbench.sh` 重建并替换旧进程，继续关联本项目、使用本地模型配置，原地址 `http://127.0.0.1:8090` 已显示新界面。重启后只读核对了页面和模型配置状态，没有触发真实模型。

涉及模型的程序流程使用本机固定响应替身，不能据此声称真实模型质量或业务架构已经通过验收。

检测器未生成目标标识及存储快照；项目无评审忽略清单。浏览器使用独立会话，截图已实际打开检查；未展示检测器覆盖层。临时服务、浏览器在验收结束后清理，截图与日志作为证据保留。
