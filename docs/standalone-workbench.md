# 独立工作台实现与验收

> 2026-09-21 决策更新：按 [ADR-0002](adr/0002-external-coding-agent-orchestration.md)，模型调用已从工作台移除。「模型与提案协议」一节的内置客户端、`POST /api/proposals` 与环境变量配置保留为实施当时的记录；当前由 `POST /api/design-request` 导出请求、`POST /api/proposal-import` 导入 agent 提案，见 [README](../README.md)。浏览器回归脚本已于 2026-09-22 改为固定响应替身扮演 agent。

实现日期：2026-09-20。产品依据为[独立图形工作台实现依据](../独立图形工作台实现依据.md)，该文件的差距表保留立项时现状。

## 已实现流程

工作台支持输入需求、AI 生成提案、点选模块或具体接口或协作线、描述修改意图、查看图形差异、继续调整或放弃、接受到草稿、单独确认整个设计版本（2026-09-22 起也可「接受并审阅确认」一步完成）、下载确认交接包。手动模块、接口、协作与禁止规则编辑继续可用；接口支持手动调整归属。

提案期间画布与详情只读，布局仍可独立调整。未保存草稿会禁用 AI 请求；生成期间不能切换项目。待审阅提案按项目保存在标签页状态中，刷新后从本项目提案档案恢复。外部草稿或确认版本改变时，提案仍可查看、下载，但不能再接受。不同标签页通过原有项目头分别访问项目。

「接受并保存草稿」只保存设计草稿。「审阅并确认」继续复核已审阅草稿指纹和预期基准。「接受并审阅确认」是前端把两步串起来：先用同一个接受接口写入草稿，成功后直接打开审阅窗口；服务端没有新增接口，草稿与基准相同且没有待确认源码依据时只提示已保存。`GET /api/handoff` 只读取磁盘的已确认快照，输出完整确认记录、设计与实现说明；从不接受浏览器提交的草稿当作交接基准。

## 数据与兼容策略

保留 `schema_version: 1`，新增可选字段：

```json
{"collaborations":[{"id":"order-refund","from":"order","interface_id":"request-refund","purpose":"取消已付款订单时申请退款"}]}
```

`interface_id` 指向接口稳定 ID，目标模块由接口的 `module_id` 决定，避免迁移接口时出现两份目标字段。协作 ID 与模块、接口和禁止规则共用命名空间。校验拒绝不存在的模块、不存在的接口、自模块接口协作和重复的调用模块与接口组合。

没有该字段的旧文件仍可读。空数组不参与 Go 序列化，旧设计指纹和历史快照保持不变；这由固定旧结构字节序列的回归验证。新程序不迁移或重写历史文件。旧程序不认识非空新增字段，需要升级后读取新设计。

协作表示能力使用，禁止规则表示 Go 直接包引用限制。两者独立：没有协作线不构成违规；同方向协作与禁止直接引用可以同时存在，例如通过注入接口实现。现有确定性检查不推导或核验运行时调用关系。

## 模型与提案协议

模型调用由 `designer` 包负责，支持 OpenAI 兼容的 Chat Completions 和 Responses。供应商、模型、密钥、协议和推理强度由进程环境配置，页面只能得知模型是否已配置。配置与启动命令见 [README](../README.md#模型配置)。默认请求严格 `json_schema` 输出；不支持时可显式设置 `ARCHDESIGN_AI_RESPONSE_FORMAT=json_object`，两种模式都执行本地 Schema、关系及项目路径校验。

实际参数依据 [OpenAI 结构化输出文档](https://developers.openai.com/api/docs/guides/structured-outputs)和[推理参数说明](https://developers.openai.com/api/docs/guides/reasoning)。严格生成 Schema 要求模型补齐接口语义和空协作数组，存储 Schema 保持原有可选字段以兼容历史。

普通需求设计的模型输入只包含总体需求、本次修改意图、所选对象和当前设计。2026-09-21 新增的源码初次分析、已有基准重新分析及其提案调整另含源码上下文，详见[初次分析实现与验收](initial-analysis.md)和[重新分析说明](reanalysis.md)。普通设计返回 `{summary, design}`，源码分析另含 `analysis` 依据；只接受完成状态的最终文本，拒绝截断、拒绝回答、意外工具调用、重复键、未知字段和无效引用。模型不能调用本机工具或确认设计。远端使用 HTTPS，本机回环模型允许 HTTP；禁止跟随重定向，供应商错误体不返回浏览器。单次模型请求沿用 `-timeout`，响应限制 4 MiB，不自动重试产生额外调用。

| 接口 | 作用 |
| --- | --- |
| `POST /api/proposals` | 携带 `requirement`、`instruction`、`selection`、`expected_draft_hash`、`expected_revision`，可选 `parent_id`；生成并保存审阅证据 |
| `GET /api/proposals/{id}` | 读取本项目的不可变提案，用于刷新恢复 |
| `POST /api/proposals/{id}/accept` | 复核生成时草稿和确认版本，在存储锁内写入草稿 |
| `GET /api/handoff` | 导出已确认快照与实现说明 |

选中对象的 `kind` 为 `design`、`module`、`interface` 或 `collaboration`，除整个设计外均须携带有效 `id`。继续调整时，以父提案的结果作为模型上下文，以原草稿作为变更对照。模型调用前核查版本，返回后在存储锁内再次核查；接受时再核查一次。后端限制同时进行的模型请求，不能用浏览器提交的地址更换模型端点。

`.architecture/proposals/<id>.json` 保存需求、意图、选择、修改输入、原草稿、结果、摘要和生成时版本；ID 是完整提案内容的哈希。提案不是确认记录，保留它只用于审阅证据与恢复。已放弃提案仍保留在磁盘；当前没有自动清理策略。

## 回归范围

Go 测试覆盖协作引用、旧指纹、模型两种协议、推理强度、取消和错误脱敏、无效结果不写草稿、生成前后冲突、跨项目提案拒绝、接受不确认、交接只读确认版，以及原存储与检查回归。

浏览器回归在临时项目中执行：

```sh
bash scripts/verify-workbench.sh
bash scripts/verify-ai-workbench.sh
```

第二个脚本启动固定响应 HTTP 模型替身，覆盖真实模型客户端到浏览器的程序链路：生成、模块拆分、接口迁移、继续修改、删除轮廓、协作详情与键盘选择、前后比较、接受、确认、交接下载和外部更新拒绝。桌面与手机截图、完整提案、确认快照和日志保存在脚本打印的 `/tmp/interface-ai-journey-*` 目录。刷新测试独立处理真实浏览器的离开提示，避免自动化提前返回被误判为完成。

固定响应回归只证明程序行为，不证明真实模型生成质量。真实模型、实际实现与人工核对证据单独记录在后续验收小节，不能用此处的回归代替。

本次确认人为「工作台验收代理（示例，不代表用户业务定稿）」。因此证据证明真实模型到图形调整、确认交接和一次实际实现的技术链路可运行，不代表用户已亲自认可界面或业务设计。尚未评估模型误报、漏报、多轮长期架构控制或自动修复。

## 界面与代码审阅

独立界面审阅发现接口/协作线与前后对照按钮重绘后焦点丢失、新增辅助文字对比度不足。已按对象类型与稳定 ID 恢复焦点，并调整新增文字颜色；真实浏览器断言通过，复核结论为 `ship`，仅覆盖这两项修复。独立代码审阅未发现阻塞问题，并补充了同时接受同一提案只成功一次、确认快照不变的并发回归。

桌面与手机截图位于本地 `.impeccable/review/`。设计检测器未能启动（本机缺少引擎，默认缓存路径不可写）；已用源码、实际浏览器和独立截图审阅补充验证，没有把未执行的检测器列为通过。
