# 工作台核心用户旅程

这些契约覆盖本地工作台的核心行为。浏览器验收使用真实 HTTP 服务和隔离的示例 Go 项目；固定语义响应仅用于验证导入与展示，不代表真实模型效果。

本文记录基础旅程及新增 AI 设计旅程。2026-09-20 按[独立图形工作台实现依据](../独立图形工作台实现依据.md)完成的模型调用、接口协作图、图形调整与实际开发验证，另见[独立工作台实现与验收](standalone-workbench.md)；固定响应回归与真实模型证据分别记录。

## 执行方式

```sh
# Go 存储、HTTP 边界与检查流程。
go test ./...

# 已安装 playwright-cli 和浏览器时，从仓库根目录运行。
bash scripts/verify-workbench.sh

# AI 设计旅程使用本机固定响应服务，无需模型密钥。
bash scripts/verify-ai-workbench.sh

# 需要指定已安装的 Chromium 时，可提供 Playwright CLI 配置文件。
WORKBENCH_BROWSER_CONFIG=/绝对路径/playwright.json bash scripts/verify-workbench.sh
```

配置示例：

```json
{"browser":{"browserName":"chromium","launchOptions":{"executablePath":"/绝对路径/chrome"},"contextOptions":{"locale":"zh-CN","viewport":{"width":1440,"height":900}}}}
```

脚本使用 `/tmp` 中的新目录，复制示例代码并创建设计，结束后停止本次服务和浏览器会话。截图、日志和临时项目保留在输出的验收目录，便于复核。需要本地监听与浏览器进程权限；依赖浏览器工具的部分不在 `go test` 内执行。

## CUJ-01：创建、审阅并确认设计

- 用户目标：约定模块职责、对外能力和禁止依赖方向，并明确决定哪份设计成为实现基准。
- 前置条件：关联尚无设计的本地项目。
- 操作步骤：创建模块；填写目录和职责；添加接口及语义；添加禁止规则；保存；在完整设计审阅窗口填写确认人并勾选审阅声明；确认版本。
- 可观察结果：目录重叠等错误在页面给出字段路径；无效草稿不落盘；有效草稿可重新读取；保存草稿不会提前改变基准；确认后保留确认人、完整内容和版本；旧草稿指纹不能确认。
- 可执行检查：`scripts/workbench-journey.js` 的创建与确认段；`workbench/TestWorkbenchEmptyProjectAndConfirmationJourney`。

## CUJ-02：与外部工具同步且不丢失编辑

- 用户目标：看到外部工具的新草稿，同时保留尚未保存的浏览器修改。
- 前置条件：工作台已读取草稿，另一窗口或命令行能够写入同一项目。
- 操作步骤：在页面修改职责；由另一调用方保存新草稿；等待同步；查看冲突；按需下载本地编辑；显式丢弃编辑并载入最新版本。
- 可观察结果：无本地编辑时自动展示外部更新；有编辑时保留输入并显示冲突，保存与确认被阻止；恢复到最新草稿需要用户选择；后端同时校验草稿指纹和确认版本。
- 可执行检查：浏览器旅程的并发修改段；`scripts/workbench-sync-regression.js` 覆盖旧轮询响应晚到、临时写锁直接重试、确认视图中的草稿备份和轮询期间主动重载；`workbench/TestWorkbenchConflictNeverOverwritesExternalChanges`；`store/TestConditionalDraftSaveRequiresBothReadVersions`。

## CUJ-03：按设计检查并核查代码依据

- 用户目标：区分明确禁止的直接依赖和模型提出的待确认判断，看到设计依据、代码位置和理由。
- 前置条件：已确认设计，项目根目录有 `go.mod`，相关 Go 依赖可用。
- 操作步骤：运行依赖检查；查看违规及源码快照；导出能力审查请求；选择原始请求和固定验收响应导入；查看语义结果；定位模块。
- 可观察结果：报告包含扫描时间和原设计版本；检查不完整时显示诊断；旧设计报告标为历史；依赖检查不能让语义状态变成通过；语义判断保持待确认且不改变设计；代码或基准变化后拒绝旧响应。
- 可执行检查：浏览器旅程的检查、代码位置与导入段；`workbench/TestWorkbenchReportsExposeViolationsAndPendingReview`；`workbench/TestWorkbenchReadsExternalArtifactsAndReportsCorruption`。

## CUJ-04：布局恢复与窄屏交互

- 用户目标：通过模块画布理解设计，调整布局，并在窄屏上继续查看和编辑。
- 前置条件：设计至少有两个模块。
- 操作步骤：在 1440×900 桌面拖动节点手柄；刷新；切换到 390×844；用方向键移动节点；选择模块并编辑；查看检查结果与冲突提示。
- 可观察结果：节点位置在刷新后恢复；布局不创建设计版本；不同窗口修改不同节点时互不覆盖；页面没有整体横向溢出，画布在自己的区域滚动；表单和确认控件仍可使用。
- 可执行检查：浏览器旅程的布局与移动视口段；`store/TestSeparateWindowLayoutUpdatesPreserveOtherNodes`。截图需实际打开审阅，截图命令成功本身不是视觉结论。

## CUJ-05：选择项目并安全切换

- 用户目标：直接在工作台输入项目路径或浏览本机目录，切换后把设计和检查结果保存到所选项目。
- 前置条件：本地工作台已启动，至少有两个可访问的项目目录。
- 操作步骤：点击「选择项目」；浏览上一级目录并选择中文路径；有未保存编辑时先取消，再明确同意丢弃后切换；在新项目保存、确认并检查；刷新；打开另一个标签页；在窄屏输入路径切回；在切换请求尚未结束时取消。
- 可观察结果：无效路径不改变当前项目；未同意丢弃时保留编辑；选择本身不创建设计文件；写入和检查始终属于对应项目；刷新恢复选择，其他标签页不被切换；切换期间禁止修改路径和重复提交，取消后晚到响应不会改变项目；桌面和窄屏入口均可使用。
- 可执行检查：`scripts/workbench-project-journey.js`；`workbench/projects_test.go` 还覆盖隐藏目录、会话令牌、布局隔离，以及初始草稿损坏时仍可选择其他项目。

## CUJ-06：生成、调整并交接设计

- 用户目标：通过需求和修改意图联动调整模块、接口与协作，审阅后将确认版交给外部实现。
- 前置条件：服务已通过环境变量配置兼容模型，当前没有未保存编辑。
- 操作步骤：输入需求并生成；选中模块、具体接口或协作线；描述修改；查看图形差异及修改前后；继续调整或接受到草稿；单独审阅确认；下载确认交接包。
- 可观察结果：提案不自动改写草稿或确认版本；接口迁移同时改变协作目标；新增、修改和删除可见；键盘选择后保留焦点；刷新恢复待审阅提案；外部版本变化阻止接受旧结果；交接只包含已确认版。
- 可执行检查：`scripts/ai-workbench-journey.js`、`scripts/verify-ai-workbench.sh`，以及 `designer`、`store/proposals_test.go`、`workbench/proposals_test.go`。固定模型只验证程序行为；真实模型与待办实现证据见[独立工作台验收记录](standalone-workbench.md#真实模型与实际实现验证)。
