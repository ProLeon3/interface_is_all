# 已有项目初次分析：工作台局部扩展

> 2026-09-21 操作层级调整：以下保留初次分析扩展时的设计依据。当前入口按项目阶段展开，已有设计先看图，通过「调整设计」进入需求修改或源码重新分析；空项目一次只展开一种起草方式。详细评审与验收见 [工作台操作层级调整与复审](../docs/ui-simplification.md)。源码发送、提案、草稿、确认及历史依据的边界继续沿用。

场景：操作型页面。用户已经选中一个 Go 项目，需要直接读代码、核对现状、编辑草稿并确认。后续扩展为已有基准项目重新分析，旧基准保持生效，直到用户确认新版本。本次不重做视觉风格。

## 方向约定

主旨：在现有源码入口中区分初次分析和重新分析，将现状、问题建议和用户确认分开。

既有风格：沿用 styles.css 的纸白、深绿、系统中文字体、普通按钮及 details 展开结构，不增加字体、插画或新设计系统。

使用过程：选择项目后看见分析按钮及发送范围说明；生成提案后先看图，再在对象详情查看源码；问题、建议、范围放在图下可展开区域；接受后仍单独确认。

首屏：原项目导航、标题与版本工具栏保留；源码入口位于需求表单之前；运行期间明确显示状态并保护已有编辑；手机布局按纵向排布。

交互：复用原提案、草稿及确认流程，保留源码查看、下载和撤回重做；重新分析提供相对旧基准的逐项差异，并说明旧禁止规则需要单独审阅。新证据即使未改变设计也能确认。所有入口具备禁用、失败和恢复状态。这是既有页面的精确扩展，不执行新视觉方案抽选。

完成条件：检查桌面和手机截图，独立复核界面和使用说明；只记录本次新增表面，不改写既有全局风格。所有既有图片继续沿用原来源，本次没有新增位图资产。
